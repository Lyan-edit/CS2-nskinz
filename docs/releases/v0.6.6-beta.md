# nSkinzCS2 v0.6.6-beta — Knife modes and panel startup recovery

Release date / 发布日期：2026-10-29. **Prerelease / 测试版**。

## 中文说明

本版修复刀具换肤路径分流和“DLL 加载返回 OK，但 Insert 打不开面板”的异常退出问题，并更新 GitHub 首页封面和真实控制面板图片。

- **模型＋饰面**只走临时 Demo 重建；配置后从原始录制生成临时 Demo，序列化刀型／模型／动画／饰面和相关刀杀信息。
- **仅饰面**只在播放中的 Demo 热修当前刀的贴图，不改刀型；在生成的临时 Demo 中也保留此路径。现代 HUD 模型从已验证的世界刀材质路径同步，按实体代际和外观签名缓存，稳定状态不重复重建。
- UI C++ 异常不再永久停用面板线程。记录失败阶段和具体异常消息；释放并重新按 Insert 可尝试重新初始化，不持续后台重试。
- 工坊目录扫描移出控制器构造，打开地图页或明确需要元数据时再扫描；坏路径、权限错误、Unicode 文件名和损坏 VPK 分别隔离。图形初始化中途失败后正确清理部分资源。
- 首页封面显示本版版本，控制面板图来自相同 MainWindow 代码的真实 D3D11 渲染，展示五槽贴纸、参数滑轨及对应枪型预览。示例配置不连接 CS2，不代表游戏内画面验收。
- 添加 `tools/update_release_artwork.py` 和 CI 检查：发版时同步封面、代码版本、面板截图来源及双语 README 图片缓存版本。

默认 T／CT 手套与挂件继续只走临时 Demo 重建。枪皮、五槽自定义贴纸、地图／雷达及 v0.6.5 的刀杀事件重建逻辑保留；内嵌 Demo 重写器没有变化。

### 使用

1. 退出并重启 CS2／HLAE，保留需要的配置，只加载一个语言版本的新 DLL。
2. 按 Insert 打开面板；如果遇到可恢复初始化错误，释放按键后再按一次。日志为 `nSkinzCS2.ui.log`；控制台 OK 只表示 DLL 已加载。
3. 刀具“仅饰面”选择涂装后点“更新”，在当前 Demo 内应用；“模型＋饰面”、默认手套和挂件配置后，生成临时 Demo。
4. 旧临时 Demo 不会因更换 DLL 自动重写。改变重建项目时使用原始录制重新生成。

### 验证与边界

55 项完整原生回归、中英文编译、便携导入／中文目录文本和隔离加载／WARP 渲染检查通过。真实 UI 测试覆盖正常启动、构造异常、部分资源异常和设备初始化失败，四种场景均成功恢复并完成原生绘制。工坊扫描专项包含坏库、长路径、非目录项、损坏 VPK 和 Unicode／emoji 文件名。

旧版日志丢弃了异常消息，不能据此认定该用户最初异常的唯一原因。测试没有注入真实键盘事件，不能等同于在报告用户的电脑上完成 Insert 验收。刀具实际贴图、游戏画面和游戏帧时间仍需实机验收；本版没有新的游戏帧时间基准。

兼容基线延续此前已核对的 CS2 Client/Server `2000935`、Patch `1.41.9.2`、Steam Build `26144732`、Source revision `11162119`；HLAE `2.192.8`／AfxHookSource2 `0.41.8`。用户日志使用 HLAE `2.192.10`，但本版不将该日志或面板恢复测试当作所有游戏功能的新版本认证，也不声称适配未核对的新 CS2 更新。

详见[刀具模式与材质链修复](../development/knife-mode-routing-live-finish-20261028.md)、[面板启动诊断](../diagnostics/ui-startup-exception-20261028.md)和[图片发布流程](../development/release-artwork.md)。

## English notes

Knife **Model + Finish** now uses Temporary Demo reconstruction exclusively. **Finish-only** hot-updates the current knife texture in the playing Demo, including generated recordings, without changing its model. Modern HUD rendering uses the verified world-knife material path, cached by entity generation and appearance signature.

Fixed the control panel remaining permanently unavailable after a UI C++ exception. Failures log their phase and exception message; release and press Insert to retry. Workshop discovery is deferred and filesystem/package failures are isolated. Partial graphics initialization is cleaned up correctly.

Default T/CT gloves and keychains retain their Temporary-Demo-only routes. Existing firearm, five-slot custom sticker, map/radar and offline knife-killfeed features remain. The embedded rewriter is unchanged.

The homepage now shows the current release cover and an unmodified native render of the current control panel. The documentation harness uses example data without a game connection. An artwork/version/provenance check runs in CI and is required for future releases.

Restart CS2/HLAE and load one new language DLL. Finish-only applies with Update; reconstruction requests need a new Temporary Demo from the original recording. Existing generated files are not repaired by replacing the DLL.

The full 55-test native suite, both builds, portable imports/localization and isolated loader/WARP gates passed. Four native UI startup/recovery scenarios passed: normal, constructor exception, partial-resource exception and device-init failure. No physical keyboard events were injected. The original log discarded the exception text, so its exact initial trigger is unknown. The reporting user's Insert behavior, rendered gameplay and frame-time effects still require in-game acceptance.

The previously checked baseline remains CS2 `2000935` / Patch `1.41.9.2` / Steam Build `26144732`, HLAE `2.192.8` / AfxHookSource2 `0.41.8`. The supplied log used HLAE `2.192.10`; this is not comprehensive certification of that environment or an unverified newer CS2 update.
