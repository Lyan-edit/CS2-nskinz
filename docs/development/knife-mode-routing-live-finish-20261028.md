# 刀具模式分流与仅饰面热修恢复

更新：2026-10-28。基于 v0.6.5 的本地修复；原生回归和 DLL 加载验证通过，**新 DLL 的实际游戏画面仍待验收**。没有覆盖 GitHub 已发布附件。

## 两种模式的执行规则

| 模式 | 执行路径 | 操作 |
| --- | --- | --- |
| 模型＋饰面 | 只写入临时 Demo | 配置目标刀型与饰面后，生成并加载临时 Demo |
| 仅饰面 | 当前 Demo 中的实时材质更新 | 点击更新，保留当前实际刀型，不生成临时 Demo |

仅饰面也适用于已经生成的 Demo。可以先重建所需刀型，再切换仅饰面调试贴图；此时保持当前生成的录制继续播放。后续若重新从原始录制重建，需重新配置希望写入的刀型。

## 日志确认的故障

本机下载目录的 v0.6.5 日志确认了目标玩家、世界刀实体 434／定义 507，以及 HUD 实例 17102：

- 21:23:17 的日志报告 HUD 贴图 fallback 字段为 568，但 `attribute_paint` 不存在。
- 同一时刻材质刷新被 `ManualOnly / epoch=closed` 拦截，随后仍出现 `Knife exact apply succeeded/queued`。
- RTTI 将该 HUD 明确识别为 `C_CS2HudModelWeapon`。它是独立渲染对象，没有可按 CEconEntity 偏移访问的 `CEconItemView`；“属性不存在”不能当作普通空物品槽处理。
- 旧的世界刀完成缓存没有绑定当前 HUD 实例，晚生成或替换的 HUD 可能被快速返回跳过。
- 另一个源码问题是临时 Demo 总开关会禁用所有刀配置，连明确选择的仅饰面也一起禁用；普通 Demo 则仍允许模型实时预备／替换。

原始日志副本与 SHA-256 留在本地 `build/knife-mode-fix-20261028/`，不作为发行依赖。

## 本次修改

1. 在实时轮询读取配置后立即过滤刀模式，后续预备、材质和模型生命周期只看到有效的仅饰面配置。过滤的是本地快照，原始配置仍供临时 Demo 生成器读取；模型＋饰面不会退化为实时贴图替换。
2. 临时 Demo 不再统一禁用仅饰面；现有默认 T／CT 手套和挂件路径保持不变。
3. 用当前武器完整 handle、Pawn／手臂归属、场景树和支持的刀模型路径确认 HUD。现代 HUD 不再进入经济物品载体选择，也不会伪造或写入 HUD item view。
4. 只有真实世界刀物品可通过既有 Schema／原生接口补齐并同步涂装属性。已验证的属性允许新饰面签名完成一次初始化，不必等待一个已经消耗的全局 Update 窗口；不安装外部属性向量。
5. 世界刀原生材质就绪后，通过已验证的原生引用计数清理／复制接口同步到 HUD。转移前后核对实体代际与归属，不调用 SetModel、subclass、动画或骨架替换。
6. 完成缓存同时绑定世界刀、HUD 实例及饰面签名；HUD 重建会失效同步状态。稳定状态不重复生成／复制材质，异步生成只等待，原生调用失败会锁定重试，等待更新或实体代际变化。
7. 仅饰面不再进入旧的刀模型／动画／providee 诊断搜索；完成快速路径仍核对当前 HUD，保留低开销缓存。界面明确显示两种模式的操作路径，字段写入不再被日志表述为材质完成。
