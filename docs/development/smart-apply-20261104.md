# 智能应用

2026-11-04。本地实现顺序：先完成枪械 HUD 名称同步和回归，再接入智能应用。

控制面板底部的“智能应用”按配置差异分流：

| 改动 | 路径 |
| --- | --- |
| 枪械涂装、刀仅饰面 | 当前 Demo 内实时应用 |
| 原始 Demo 中已确认的非默认手套，仅饰面 | 当前 Demo 内实时应用 |
| 刀模型、手套模型、默认 T／CT 手套 | 临时 Demo 重建 |
| 贴纸、挂件 | 临时 Demo 重建 |
| 地图／雷达配置 | 准备资源后重载 Demo |

手套载体信息由运行时后台每秒发布。未确认、过期或生成 Demo 内的手套保留重建保护，不进入实时写入。游戏暂停或尚未解析玩家时，面板可能显示“暂未确认手套载体，将使用 Demo 重建”。

画布和滑轨即时反映编辑数据；贴纸及挂件在游戏内的效果于重建后应用。雷达编辑也先暂存，点击智能应用后准备并重载。

实时改动单独应用时不重建。混合配置先在后台生成临时 Demo，成功后发布实时配置和加载命令。生成失败不会提前发布本次配置；生成期间暂时禁用编辑，源 Demo 变化会阻止旧结果自动加载。面板显示的是命令已排队，不代表游戏已完成加载。

首次使用尚未捕获源路径时，按钮先激活运行时捕获，不保存本次暂存配置。捕获到原始路径后自动继续；十秒内未取得路径会提示先加载原始 Demo，并恢复编辑。

从原始 Demo 再次重建时保留当前所有重建覆盖，避免新增挂件时丢失此前贴纸。取消重建覆盖需要重新生成或重载原始 Demo。未修改的配置不重复重建，配置列表名称和预生成雷达路径不计作饰品变化。

HUD 名称同步见 [枪械名称诊断](../diagnostics/firearm-hud-name-20261104.md)。标准右侧武器列表没有手套名称行。自动化回归和独立面板截图不代替游戏内的最终画面验收。

2026-11-05 补充：临时 Demo 饰品重建在界面和生成入口共同检查目标 XUID。所有饰品配置均未启用或 XUID 都为零时，页面显示提示；点击生成会弹出原因说明并取消，不启动重写器。提示明确区分地图替换：仅换地图不需要 XUID，应通过智能应用准备地图资源并重载 Demo。

“已填写 XUID，但未匹配到对应枪械挂件记录”是另一类失败，界面另行提示检查启用状态、目标玩家和枪型。单独修改地图且饰品重建配置未变时，智能应用只重载当前播放文件，保留其中已重建的饰品，不再为地图改动重跑挂件／贴纸重写。

v0.7.1 修复刀的模式切换：智能应用把已重建模型事务与当前仅饰面编辑分开记录。模型＋饰面切到仅饰面是实时饰面改动，不再算作撤销模型。后续其它饰品触发重建时，使用保存的模型事务保留刀型，再由实时仅饰面配置应用新的涂装。只有明确禁用／删除对应刀配置时，才把该模型覆盖计为需要撤销；重新加载原始录制会清理本次播放记录。新鲜的仅饰面配置中隐藏的模型值不会被提升为重建请求。
