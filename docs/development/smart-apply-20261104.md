# 智能应用

2026-11-06 更新：应用范围改为当前项，修复底部全局按钮把其它暂存改动一起提交的问题。

## 独立按钮

| 按钮 | 提交范围 | 路径 |
| --- | --- | --- |
| 智能应用此枪涂装 | 当前 XUID、当前枪型的涂装、磨损、Seed、品质、StatTrak、名称 | 当前 Demo 实时应用 |
| 智能应用当前贴纸槽 | 当前枪械选中的一个贴纸槽 | 临时 Demo 重建 |
| 应用此枪全部 5 个贴纸槽 | 当前枪械的五个贴纸槽 | 临时 Demo 重建 |
| 智能应用此刀配置 | 当前 XUID 的一条刀配置 | 仅饰面实时；模型＋饰面重建 |
| 智能应用此手套配置 | 当前 XUID 的一条手套配置 | 已确认的原始非默认手套仅饰面实时；模型、默认 T／CT 手套、生成 Demo 手套重建 |
| 智能应用此挂件 | 当前 XUID、当前枪型的一条挂件配置 | 临时 Demo 重建 |
| 智能应用地图更换 | 地图与雷达配置 | 准备地图资源并重载当前播放文件，无需 XUID |

例如同时暂存 AK 贴纸和刀仅饰面，点击刀按钮只提交刀饰面，既不提交贴纸，也不重建 Demo。枪械涂装和贴纸分开合并：应用枪皮保留已应用的贴纸；应用一个贴纸槽保留当前枪皮和另外四个槽位。其它玩家、其它枪型的已应用配置继续保留。

需要重建当前项时，以“上一次已应用配置＋本次当前项”为输入，从原始录制重新生成，保留已经应用的其它重建效果。编辑器中尚未应用的其它改动、未填写 XUID 的其它配置不进入本次事务。刀仅饰面不会因为其它项存在重建改动而改走重建。

地图／雷达资源准备也独立：应用刀或枪皮不会再次清理、解码或编译雷达。地图按钮可保留当前临时 Demo 中已经重建的饰品。

## 仅饰面的模型识别

在刀／手套页面选择仅饰面，填写目标玩家的 XUID，并加载、播放 Demo。面板请求运行时读取这个玩家的当前模型；这个请求只读取模型，不发布编辑器里的外观配置。手套模型来自 Pawn 的手套物品视图，原皮按已读取的阵营解析。刀模型来自目标 Pawn 所持武器，并检查武器完整句柄及拥有者，遇到冲突不猜测。

界面显示“已识别当前模型”。只有对应模型兼容的涂装才进入下拉列表：刀不显示枪械涂装，也不显示其它刀型独有的涂装；手套只显示当前手套型号的涂装。模型未确认时，饰面选择和已启用配置的应用按钮禁用，不回退到全部目录。读取结果过期后重新等待识别，可点击“重新检测当前模型”重新激活查询；点击应用时再次读取最新结果并校验兼容性。原配置中的不兼容涂装不会被悄悄替换成其它涂装，需重新选择。

默认刀和默认手套没有特殊模型对应的饰面。需要换成其它型号时使用模型＋饰面。默认 T／CT 手套以及生成 Demo 中的手套继续遵守临时 Demo 重建保护，不进入实时创建实体或修改模型路径。

模型查询每秒发布，查询结果有效期五秒；没有外观配置时，只读查询最多每半秒扫描一次。关闭页面后查询过期，不保持额外后台扫描。

## 编辑与应用分离

- `nSkinzCS2.json` 保存编辑器内容。保存／加载只操作暂存设置。
- `nSkinzCS2.applied.json` 保存已按项应用的配置，运行时只读取这个文件。
- 升级后，旧编辑器配置保留，但不会自动当成已应用配置。按所需项逐一点击应用；成功应用也不会清除其它暂存内容。
- “临时换肤 Demo”页保留明确标注的高级操作“应用全部已启用配置并重建 Demo”。它是主动批量操作，与各项智能应用按钮区分。

首次需要重建但尚未捕获源路径时，按钮先激活运行时捕获，不发布暂存配置。取得路径后继续同一个项；十秒内未取得路径则恢复编辑并提示先加载原始 Demo。生成失败不发布本次配置；生成期间禁用编辑，源路径变化会阻止旧结果自动加载。命令已排队不代表游戏已完成加载。

切换刀的模型＋饰面到仅饰面会保留当前重建模型。随后重建其它项时保留已成功重建的刀型事务，再实时应用当前仅饰面配置；隐藏的旧模型值不能代替当前模型识别。

HUD 名称同步见[枪械名称诊断](../diagnostics/firearm-hud-name-20261104.md)。标准右侧武器列表没有手套名称行。本次不启动 CS2 或 HLAE；自动化与独立原生面板检查不代替游戏内最终画面验收。
