# 故障排除与反馈模板

适用版本：v0.7.6。先确定失败发生在哪一步，再提供对应证据。

## 加载返回 ok，按 Insert 不出现面板

1. 核对加载的是当前 DLL，且没有叠加另一语言或旧版。
2. 返回 CS2 窗口按 `Insert`／`Ins`；笔记本检查键盘组合。
3. 查看任务栏，确认面板是否已打开在后台或其它显示器。
4. 检查 DLL 文件夹可写，并查看 `nSkinzCS2.ui.log` 的启动、窗口、首帧和图形错误；同时保留 `nSkinzCS2.log`。
5. 升级或加载状态不确定时，完整重启后只加载一次，复现并保留新日志。

`ok` 不是面板首帧成功的证明。不要通过向同一进程反复加载多个 DLL 排查。

## 点击应用没有变化

| 检查 | 常见原因 |
| --- | --- |
| 是否勾选启用，并点击了正确项目的应用 | 保存／编辑／切换列表没有提交 |
| XUID 是否属于这份 Demo 的当前持枪者 | 复制了另一份录制的玩家，或填了原购买者 |
| 当前实际枪型是否匹配 | M4A4 与 M4A1-S 等不是同一规则 |
| 仅饰面的当前模型是否已检测 | 模型未知时不能使用其它型号的皮肤列表 |
| Demo 是否刷新画面 | 暂停时可短暂恢复播放 |
| 运行时是否就绪，目录是否有效 | 更新后的签名、资源或兼容数据尚未确认 |

只改刀却看到此前配置的枪也变化时，先检查这把枪是否已在**本会话**应用过；独立按钮不撤回先前的明确应用。重新启动后仍出现不明自动应用，再附会话日志反馈。

## 默认 T/CT 手套不变

确认使用手套“模型＋饰面”，选了真实目标型号与该型号涂装，XUID 是当前观察玩家，并点击手套应用。查看旧 Demo 模型兼容提示与已知失败记录。

v0.7.6 不通过临时 Demo 重建手套。生成一个只有手套配置、没有挂件规则的临时 Demo 不能解决这个问题。

## 右侧刀名／枪名还是旧的

同时保留实际外观、右侧 HUD、配置模式、型号、涂装、XUID 和 tick。先刷新画面、核对当前持枪者与版本。配置名称不是改名字段；左下卡片更新也不能代替右侧同步验证。详见[HUD 与名称](HUD-and-Names.md)。

## 贴纸重合、第五槽看不见或移出枪体

逐槽通过编号选择，确认黄色高亮对应正在调整的槽；检查是否已点击当前槽应用。先使用预设位置、正常倍率，再以很小的步长移动。

确认预览枪型和新／旧模型一致。贴纸透明留白、曲面和透视可能使实际图案与预览块不同。提供所有五槽的图案、缩放、旋转、X/Y 与自定义开关，不能只提供一张游戏图。

## 挂件重建失败

先分辨：源文件打不开、找不到玩家／枪械、解析／写入失败、输出验证失败，还是已生成但加载命令不可用。

查看最新任务中的完整 `rewriter.log`，附当前挂件规则与源 Demo。若提示无匹配挂件武器快照，重点核对 XUID 和枪型；若出现 panic／字段表／序列化异常，需要完整错误栈及可复现源文件。

不要把挂件新增失败笼统称为“刀或手套重建失败”；本版这些项目不经过重写器。

## 临时 Demo 卡在加载页或游戏闪退

1. 记录开始加载时间、完整任务日志与游戏错误；截图加载页不够定位。
2. 完整重启后加载**原始 Demo**，确认源录制是否正常。
3. 分开复现挂件重建、地图替换和热修外观，确定最小触发组合。
4. 若原始文件正常而临时文件失败，提供两者的路径标识／摘要及生成规则；不要覆盖源文件。
5. 若换新模型后闪退，附型号、旧 Demo 兼容提示与热修日志，避免重复触发已知失败组合。

## 地图没切换、雷达黑底或缺道路

确认订阅下载完整、扫描到正确顶层地图，点击使用选中地图后再点击地图应用，并等待重载。单纯换图不需要 XUID。

区分整圆黑底、图片内部黑块与世界几何缺失。命中固定参考时，道路恢复／容差可能被禁用；`inferno_water` 固定标准不因这些滑轨改变。附工坊 ID、内部地图名与参数，见[地图与雷达](Workshop-Maps-and-Radar.md)。

## 卡顿排查

在相同 Demo、tick 区间、视角和图形设置下，分别记录未加载 DLL、加载未应用、单独应用某一模块的帧时。临时 Demo 生成阶段的 CPU／磁盘开销与持续播放帧时分开统计。

避免多个外观 DLL 并存。记录 CS2/HLAE 版本、分辨率、是否录制及最小触发项；平均 FPS 不足以证明偶发卡顿已消失。不要为排查而盲目删除兼容保护记录。


日志与可复现录制不足时，只能判断方向，不能保证凭截图确认根因。请保留完整错误文字。
