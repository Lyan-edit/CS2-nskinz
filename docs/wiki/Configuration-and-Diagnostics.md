# 配置、目录、会话与日志

适用版本：v0.7.6。多数旁文件位于加载的 DLL 所在可写目录；任务文件与兼容历史另存于临时目录。

## 主要文件

| 文件／目录 | 用途 |
| --- | --- |
| `nSkinzCS2.json` | 用户保存的编辑器配置 |
| `nSkinzCS2.session-<CS2 PID>.applied.json` | 当前 CS2 进程已明确应用的规则 |
| `nSkinzCS2.catalog.json` | 从本机游戏数据导出的目录旁文件；实际生成情况以日志为准 |
| `nSkinzCS2.log` | DLL、运行时、应用与加载诊断 |
| `nSkinzCS2.ui.log` | 独立控制面板的启动、图形与任务诊断 |
| `%TEMP%\nSkinzCS2\skin-rewrite-*\` | 临时 Demo 任务，重点检查 `rewriter.log` |
| `%TEMP%\nSkinzCS2-live-test-0.7.5\` | 为保留历史继续沿用的热修诊断／兼容目录；含 `nSkinzLive.log` 等记录 |

临时目录保留旧版本字样不代表加载了旧 DLL，应核对 DLL 文件名、摘要和版本日志。不要为了“清理”而删除已知失败模型的兼容记录，这会丢失保护线索。

## 应用会话

每次在 CS2 进程加载 DLL 时，应用会话初始化为空。历史 `.applied.json` 不会自动激活保存过的整套饰品；同一个 PID 被系统复用时也应重新初始化。

关闭／重开控制面板保留本次进程已应用的项目。切 Demo、回跳、换图或挂件重建仍处于同一进程时，已应用规则可能继续匹配新出现的实体。想重新开始，请重新启动，并只应用本次需要的项目。

**编辑器文件用于继续编辑，应用文件用于会话维护。不要手改 PID 应用文件来代替点击应用，也不要把别人的会话文件复制成自己的运行状态。**

## 配置迁移

1. 完整退出 CS2，备份编辑器 JSON。
2. 正式版配置继续使用 `nSkinzCS2.json`。
3. 来自此前测试包的 `nSkinzCS2.live-test.json`，可备份后复制为正式文件名。
4. 加载新 DLL，使用加载恢复编辑器，核对 XUID、模式与兼容涂装。
5. 对需要的项目分别应用，再保存。

不要直接覆盖新会话文件。旧配置中的品质或历史分流字段，不等于当前面板还支持对应的手动行为。

## 目录如何更新

目录来自本机安装的 CS2 物品定义、库存图标和语言资源。枪械／刀按模型筛选，手套按型号匹配；并非面板少显示就意味着完整目录已经删除。

遇到“不可用”、数量异常或名称缺失时，核对客户端版本、安装路径和日志中的目录来源。安装资源未确认时，面板可能限制可选项。不要用网上随意复制的旧目录文件覆盖来扩大选项。

## 运行时调试信息

面板底部“运行时调试信息”可收起，按需展开查看运行时状态、详细说明、帧回调、Demo／Schema／实体状态、目录警告与错误。不同路径的某些历史计数可能为空，不应仅凭一个旧计数断言当前功能失败。

“就绪”表示基础运行条件；判断某个项目是否成功，还要看该次应用结果与实际画面。遇到失败时保留完整上下文，而不是只复制最后一个 `ok`。

## 提交诊断前

保留原始日志供本机核对。公开提交时遮去本机用户名、私人目录、无关玩家身份与访问凭据；保留必要的版本、型号、错误栈和 tick。源 Demo 的公开下载地址应由提供者确认可分享。

可直接使用[故障反馈模板](Troubleshooting.md)组织报告。
