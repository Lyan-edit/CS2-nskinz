# 基本工作流与独立应用

适用版本：v0.7.6。

## 配置给谁

XUID 是玩家的 SteamID64，通常是一串 17 位十进制数字。不要填昵称、队伍编号、实体编号或短 SteamID。

枪械按 **当前持枪者 XUID＋枪型** 匹配；刀和手套按对应玩家 XUID 配置。捡起队友的枪后，填写现在持枪的玩家，而不是那把枪最初的购买者。T、CT 换边后仍以玩家身份匹配，不需要把队伍名称当作 XUID。

应从 Demo 的可靠玩家资料或对应玩家 Steam 资料确认 SteamID64。若运行时诊断提供当前观察玩家，可用它辅助核对。不能把旧配置中的数字直接当作新 Demo 一定存在的玩家。

## 配置名称与游戏内名称标签

| 输入框 | 作用 |
| --- | --- |
| 配置名称 | 给左侧规则起名，例如“选手 A 的 AK”；方便管理，不是游戏内改名 |
| 游戏内名称标签 | 对匹配到的物品设置自定义名字，供相应游戏显示使用 |

当前两种输入框用途不同。需要同步饰品标准型号／涂装名称时，使用对应外观配置并应用；不需要把标准皮肤名称抄到“配置名称”。详见[HUD 与名称](HUD-and-Names.md)。

## 编辑、保存、应用分别做什么

| 操作 | 结果 |
| --- | --- |
| 修改下拉框、数值、复选框、预览位置 | 暂存在编辑器中 |
| 保存 | 把编辑器内容写入 `nSkinzCS2.json` |
| 加载 | 从该文件恢复编辑器内容 |
| 当前项智能应用 | 将这一项合并到本进程已明确应用的配置中 |
| 隐藏／重开面板 | 保留同一进程已应用的项目 |
| 重启 CS2 并重新加载 DLL | 新建空应用会话，需要重新点击各项应用 |

“启用”是这条规则的一部分。勾选后仍需应用；取消勾选也需点击对应应用，才能提交停用。删除左侧配置只会编辑规则列表，不应把删除当作即时撤回按钮。

## 每个按钮只应用当前项

例如，你已编辑 AK 涂装、AK 的 1 号贴纸和蝴蝶刀饰面：

1. 点击“智能应用此枪涂装”：只提交该枪的涂装及相关饰面参数，未提交的贴纸和刀仍暂存。
2. 点击刀的应用：只提交该刀配置，不因其它页面暂存了挂件而启动重建。
3. 点击“智能应用当前贴纸槽”：只提交所选槽；点“全部 5 个贴纸槽”才会提交该枪五槽。
4. 点击挂件应用：为挂件重建临时 Demo；本会话此前已应用的热修项目会继续维护。

“仅当前项”不会抹掉此前已经应用的其它项目。如果要观察纯原始效果，可重新启动并加载原 Demo；源 Demo 自带的饰品仍会存在。

## 建议的配置顺序

1. 加载并正常进入源 Demo，确认目标玩家当前持有对应枪械。
2. 新增或选中配置，填写正确 XUID，勾选启用。
3. 先应用一个容易辨认的涂装，确认目标和匹配规则。
4. 再调整磨损、种子、名称、贴纸或挂件。
5. 每次调整后点击对应按钮；要长期保留编辑结果，再点击保存。

为同一 XUID 与枪型维护一条明确的有效规则。重复建立多条互相冲突的规则会增加排查难度。

## 暂停与回跳

热修与 HUD 更新依赖游戏帧回调。Demo 暂停且画面未刷新时，可短暂恢复播放，再确认效果。回跳或重载可能让源记录重新写入实体，本会话已应用规则会继续维护；这不等于保存文件被自动全量启用。
