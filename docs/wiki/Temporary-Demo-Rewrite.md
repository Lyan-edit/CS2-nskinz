# 临时 Demo 重建

适用版本：v0.7.6。**本页只重建挂件。枪械涂装、刀、手套与贴纸应使用各自的热修按钮。**

## 什么时候使用

新增挂件、替换已有挂件、清除挂件或改变挂点时使用重建。创意工坊换图使用地图页的应用按钮，不需要为了换地图创建挂件规则或填写无关 XUID。

## 源文件

先播放原始 Demo。程序会尝试捕获当前源路径；必要时在“原始 Demo 文件”中填写本机有效的 `.dem` 路径。

保留原始文件作为后续每次挂件重建的输入。不要把上次生成的临时 Demo 当作原始录制，也不要把一个有效路径理解为其中必然包含当前配置的玩家和枪械。

## 两个入口的区别

| 入口 | 提交范围 |
| --- | --- |
| 挂件页“智能应用此挂件” | 当前选中的挂件项，并保留本会话已应用的其它挂件规则 |
| 临时 Demo 页“高级：应用全部已启用配置并重建 Demo” | 当前编辑器中可用于重建的挂件配置；提交前检查所有挂件条目 |

日常只改单个挂件时优先使用该项的智能应用。临时 Demo 页面可检查源路径、请求统计和完整结果。

高级按钮保留了“全部已启用配置”的历史名称，但本版入口已经过滤为挂件，不会把枪械、刀、手套或贴纸写入生成文件。

## 生成与加载流程

1. 检查至少有一条启用的挂件规则，XUID 非零，枪型和挂件选择有效。
2. 核对源路径后开始生成，等待任务结束；期间不要反复点击生成。
3. 重写器解析源录制，匹配玩家／枪械，生成新文件并重新解析验证。
4. 验证成功才请求 `playdemo` 加载生成文件。原始 Demo 不覆盖。
5. 重新进入后，定位到目标玩家实际拿到该枪的时间点，检查挂件。

本会话已应用的枪械、刀、手套和贴纸继续由热修维护，不会因此写入新的 Demo 文件。把生成文件单独交给另一台未加载 DLL 的电脑时，不能期待它包含这些热修外观。

## 缺少 XUID 的提醒

挂件重建需要将规则匹配到录制中的真实玩家和对应枪械。如果没有启用且含有效 XUID 的挂件配置，程序会提醒并阻止无目标重建。

只换地图时不需要 XUID，直接使用地图页。如果需要挂件，不能填写一个不属于该 Demo 的随机 XUID 来消除提醒。

## 已生成但没进入回放

如果结果说明文件已生成，但播放命令桥暂不可用，待运行时就绪后可点击“再次加载生成的 Demo”。这会重新请求加载已有产物，不等于再重写一份文件。

生成失败、产物验证失败和游戏加载失败是不同阶段。UI 显示重建成功不代表游戏已完整进入，详见[故障排除](Troubleshooting.md)。

## 任务日志

一般在 `%TEMP%\nSkinzCS2\` 下查找最新的 `skin-rewrite-*` 任务目录，保留其中的 `rewriter.log`、请求和结果文件（实际存在的文件以该任务为准）。

报错如“未验证到匹配的挂件武器快照”时，优先核对玩家、枪型、源 Demo；解析 panic、字段表或序列化错误则需要原始完整日志及可复现源录制。不要只截取结果栏第一行。
