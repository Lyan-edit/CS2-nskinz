# Temporary Demo fixed8 解析修复

2026-11-14，基于 v0.7.3 的本地修复。

## 复现与根因

用户提供的 `9.dem`，92,085,460 字节，SHA256：
`dd239d03e9b3825abfd714d66f5d6db6dcba98887549022bb5a4bd6e55dcb0a5`。

原版内嵌重写器在发现阶段稳定退出：`serializer.rs:132:59`，
`index out of bounds: the len is 0 but the index is 0`，且没有生成 response.json。
调用链为 `discover_from_slice → entity_updated → read_fields → get_decoder`。

针对首个实体包的诊断确认：tick 0 的玩家 Pawn 动画字段
`m_SerializePoseRecipeAG2Dynamic` 类型为 `CNetworkUtlVectorBase<uint8>`，
其发送表明确声明 `encoder=fixed8`。旧解析器没有识别该编码，将元素按变长整数读取。
高位字节使读流错位，随后将后续比特解释为对空实体槽位的更新，最终触发越界。
空字段表是读流错位后的结果。

## 修复

- 根据发送表的 `fixed8` 声明，为 uint8 选择固定 8 位编解码器；同时实现 decode、skip 和 encode。普通 uint8 保持变长编码。
- 覆盖向量泛型元素的实际 Serializer 路径，适用于声明相同编码的其它录制和字段。
- 重写器 panic 转为失败 response.json，保留错误正文；原始日志保留完整源码位置。
- Logger 使用显式 UTF-8 写入即时及延迟日志。旧宽字符文件流会在中文编译路径 `E:\codex项目` 处停止写入，连换行和后续错误正文也会丢失。
- 重建日志记录任务目录，错误摘要附完整 rewriter.log／response.json 路径。
- 默认 T／CT 手套保持临时 Demo 重建路线。
