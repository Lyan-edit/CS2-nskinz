# 刀具右侧 UI 名称与实际涂装不同步（2026-10-31）

## 现象

刀具的模型或实际材质已经切换成功，但右侧武器栏仍显示上一次刀具的本地化名称，例如实际画面已不是虎牙，UI 仍显示“爪子刀（★）| 虎牙”。该问题同时可能出现在：

- “仅饰面”：原 Demo 播放期间的材质热修；
- “模型+饰面”：临时 Demo 重建后再次加载同一刀型、不同涂装。

这不是击杀信息图标问题，也不是材质生成失败。右侧武器栏使用经济物品身份缓存本地化刀名和涂装名；材质字段正确并不代表这个名称缓存已经失效。

## 根因

0.6.6 的临时 Demo 刀具身份由“玩家 XUID + 刀型”生成，没有把 `paint_kit` 纳入身份。同一玩家保持刀型不变、只更换涂装时，重建后的 `m_iItemIDHigh:m_iItemIDLow` 与上一份临时 Demo 相同。CS2 因而可复用旧的 UI 名称缓存，但渲染仍读取新涂装属性，于是出现“实际材质已变、UI 名称未变”。

实时“仅饰面”链还会保留来源刀具的真实库存高位 ID。即使动态属性与 fallback 涂装已经更新，右侧 UI 仍可能从原库存身份取得旧名称。原快速路径只核对涂装属性和材质数量，没有把用于 UI 的完整经济物品身份、`m_bDisallowSOC`、初始化状态与名称字段纳入稳定状态验证，错误缓存因此可能被当作已完成状态跳过。

## 修复

### 模型+饰面：仍然只走临时 Demo

- 临时 Demo 重建器现在用“玩家 XUID + 目标刀型 + 目标 `paint_kit`”生成独立的刀具经济物品身份；刀型相同但涂装变化时，高低位 ID 都会变化。
- `player_death` 中的 `weapon_itemid` 使用与刀实体相同的新身份；`weapon_fauxitemid` 继续编码目标刀型和涂装。因此右上角击杀信息与右侧武器栏不会使用两套互相矛盾的身份。
- 没有把模型、动画、Subclass 或材质替换重新接入实时模型链。模型+饰面的模型和涂装来源仍完全是临时 Demo 重建。

### 仅饰面：仍然只走 Demo 内热修

- 显式刀具涂装不再保留来源库存高位 ID，而是生成带命名空间、随“玩家 + 当前刀型 + 涂装”变化的客户端身份；同时继续写入新的材质缓存低位 ID并设置 `m_bDisallowSOC`。
- 稳定快速路径现在验证完整经济物品状态，而不只验证三个涂装属性。身份、SOC 脱离、初始化、账户、质量、fallback 或名称字段任何一项被 Demo 复制回旧值，都会重新进入一次有界修复；材质完成且所有字段稳定后仍走原有低开销快速路径。
- 仅饰面路径不会写刀型定义、模型、动画图或 Subclass。

## 回归门禁

- C++：验证相同玩家和刀型在 `paint_kit` 改变时 UI 身份必然变化，并确认新身份不等于来源真实库存 ID。
- Rust：验证临时 Demo 刀具身份随涂装变化且保持在 nSkinz 客户端命名空间；刀实体与击杀事件使用相同身份。
- 路由：`FinishOnly` 仍只进入实时饰面管线；`ModelAndFinish` 仍只由 `BuildDefaultDemoSkinRewritePlan` 写入临时 Demo，不允许退回实时模型替换。

## 游戏内验收

1. 完全退出仍加载旧 DLL 的 CS2/HLAE 进程，再加载新构建。
2. 仅饰面：保持同一刀型，连续选择两个名称不同的涂装；确认实际材质、右侧刀名/涂装名同步变化，切枪、seek、暂停恢复后仍一致。
3. 模型+饰面：从原 Demo 分别生成两份“同刀型、不同涂装”的临时 Demo；每次用生成按钮重新加载，确认右侧 UI 名称与画面一致。
4. 用刀击杀时同时确认右上角击杀图标、事件刀型与右侧武器栏一致。

离线字段回读、构建和自动测试不能代替 Panorama 的实际画面验收；如果游戏内仍显示旧名称，需保留新 DLL 的 `nSkinzCS2.log`、`nSkinzCS2.ui.log` 和对应生成 Demo，继续检查当前版本新增的 UI 消费者缓存。
