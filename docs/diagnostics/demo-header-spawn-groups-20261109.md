# 临时 Demo 场景资源索引修复

2026-11-09，反馈版本 v0.7.2。未启动或操作 CS2／HLAE；本轮已完成文件差异定位、修复产物和本地 DLL 验证，最终游戏内加载仍待实测。

## 原始证据

失败录制：`natus-vincere-vs-falcons-m1-ancient.dem`。本机日志中重建约 35 秒完成，随后分发 `playdemo`。地图更换关闭。旧离线校验报告饰品读回成功，但没有检查场景资源组索引。

PBDEMS2 的 16 字节文件头中，字节 8–11 指向 FileInfo，字节 12–15 指向 SpawnGroups。此次重写后表的位置如下（单位：字节）：

| 文件 | FileInfo 实际位置 | SpawnGroups 实际位置 | 文件头声明的 SpawnGroups 位置 |
| --- | ---: | ---: | ---: |
| 原始录制 | 410708872 | 410707258 | 410707258 |
| 旧重建产物 | 410734064 | 410732450 | 410707258 |
| 修复产物 | 410734064 | 410732450 | 410732450 |

旧重写器回填了 FileInfo，遗漏 SpawnGroups。饰品字段使文件增长 25,192 字节后，旧索引落到普通数据包内部，不能作为有效的场景资源组入口。引擎加载资源使用此索引，足以造成卡在地图加载页的现象。顺序解析器直接从字节 16 扫描，忽略第二个索引，因此旧的“验证成功”没有发现这个错误。

另一个独立录制的原始 SpawnGroups 位于 405383898，旧重建后实际位于 405443446，但声明仍是旧值，说明此缺陷不限于 Ancient。

## 修复

- 写出压缩或原始命令时，分别记录两个索引在输出文件中的位置，在收尾时一起回填；不存在的组索引归零，超出 u32 表达范围则报错。
- 在饰品验证前增加独立的容器扫描：检查命令边界、长度及两个文件头索引。扫描继续越过 DemStop，因为资源组与 FileInfo 可以位于它之后。不再允许“饰品正确但资源入口损坏”的文件自动加载。
- 不接入实时饰品代码，不改变默认 T／CT 手套的临时 Demo 路径。

## 验证与交付

- 29 项普通 Rust 回归通过，包括命令增长／缩短、压缩／原始输出、不含资源组、删除资源组以及陈旧／截断索引拒绝。
- 6 个真实文件用例通过：3 份原始录制有效，2 份旧重建产物被拒绝，修复产物有效。
- 使用失败时同一份请求重新生成 410734082 字节的临时 Demo。与旧产物完整比较，仅字节 12、13、14 不同，场景表索引的 4 字节字段被修正；其余全部字节相同。刀、枪皮、手套数据未变。
- 新文件通过饰品读回：1 个手套目标、168442 条手套记录、59 个创建快照、19 个刀实体、7 个枪械实体以及 156 个死亡事件。
- 中文修复 DLL 已确认内嵌新重写器，隔离加载和内嵌着色器检查通过。仍使用 v0.7.2 内部版本号，以 `demo-header-fix` 文件名区分；没有覆盖 GitHub 正式版附件。

本地证据：`build/diagnostics/demo-load-20261109/`。旧文件及原始录制保持不动。交付位于工作区 `build/Release/`：修复 DLL，以及 `nskinz_skin_ancient_header_fixed.dem` 和对应清单。可以直接测试修复文件，也可以退出旧 DLL 所在进程后加载新 DLL，从原始录制重新生成。不能仅凭上述离线检查宣称已完成游戏内加载验收。
